# Alfred 提醒手动协作 · 1.2.0/build30

本接口在 `--agenda` 模式按需运行，退出后不保留服务。正常菜单栏及日历行为保持原样。开发/权限批准不是任何个人事项的写入或删除批准。

## 能力与真实边界

| 字段/行为 | 读取 | 写入 |
| --- | --- | --- |
| 列表身份、source/calendar/AppleID | 支持 | 保留，不搬移/新建列表 |
| title、dueDate/dueTime/dueTimeZone、priority | 支持 | 普通新增、精确更新 |
| notes | 精确ID显式选择；nil与空串区分 | replace / append / clear；保留原文及无关字段 |
| isCompleted | 核心字段 | 完成true / 恢复未完成false；只限人类核对的独立事项 |
| completionDate | 显式投影；允许完成但原生日期nil | 不接受输入；完成由原生setter记当前时间，恢复未完成由原生setter清空 |
| 单项删除 | 精确身份核对/删后不存在回读 | 有条件支持；非重复/非邀请独立事项，具体批准+不可恢复风险声明 |
| 原生父/子/子任务数量 | **UNKNOWN，不支持关系读取** | 不支持创建/调整关系、连带完成或删除 |
| 恢复被删除事项/清空最近删除 | 无公开实现 | 不支持；JSON导出是证据，不是原生恢复 |
| URL、闹钟、location、开始日期、重复、邀请、排序、标签、分组、附件 | 不在提醒投影范围 | 不写；不使用私有数据库/接口 |

本机公开SDK的EKReminder提供dueDateComponents、isCompleted、completionDate、priority，继承EKCalendarItem.notes，但未提供parent/children关系属性。能力命令把childCount保留未知，不把扁平条目称为独立事项或将标题缩进冒充关系。替代方案是由本人在系统提醒应用执行真正缩进/取消缩进，再以精确ID人工核对；其他可选平铺清单或外部关系表也不能称原生子任务。本版本不创建这样的替代存储。

Apple说明完成、删除、移动父任务会连带影响子任务。因此已有事项完成/恢复/删除须先在系统原生界面确认“无父任务、无子任务”，填写下述人类核对记录，且15分钟内预览/执行。此人类核对不是API证明；关系本身的手机并发修改无公开检测能力，不能保证跨设备原子保护。存在/未知父子关系的事项停在人工处理，不以接受连带风险绕过。

Apple系统提醒应用一般将删除内容保留在“最近删除”30天，但适用账户/系统及EventKit remove实际路由未做破坏性验收。本接口无撤销/原标识恢复方法，不承诺接口删除可恢复；没有清空最近删除/永久删除功能。显式allowIrrecoverableDelete=true和具体操作批准必需。未满足条件一律拒绝。

来源：[EventKit EKReminder](https://developer.apple.com/documentation/eventkit/ekreminder)、[完成语义](https://developer.apple.com/documentation/eventkit/ekreminder/iscompleted)、[子任务与连带影响](https://support.apple.com/guide/reminders/add-subtasks-to-reminders-remn32a9622b/mac)、[系统删除及恢复](https://support.apple.com/guide/reminders/delete-reminders-remna83c9566/mac)。

## 权限与限范围读取

统一正式入口：`~/Applications/Alfred.app/Contents/MacOS/SuiAssistant`。不要调用历史清理过的候选。

```sh
~/Applications/Alfred.app/Contents/MacOS/SuiAssistant --agenda capabilities
~/Applications/Alfred.app/Contents/MacOS/SuiAssistant --agenda reminder-status
# 仅取得本人的同一进程权限批准且status尚未授权时，调用一次；已授权跳过。
~/Applications/Alfred.app/Contents/MacOS/SuiAssistant --agenda request-reminder-access --user-approved-privacy-request
# 另启动一个独立进程复查，不能用申请回调替代此证据。
~/Applications/Alfred.app/Contents/MacOS/SuiAssistant --agenda reminder-status
~/Applications/Alfred.app/Contents/MacOS/SuiAssistant --agenda reminder-inventory
```

须记录实际启动上下文及新鲜权限。本机在平台批准的正常Mac命令上下文直接运行正式可执行文件已验证fullAccess和限范围读取；受限命令和open路线曾返回notDetermined，与常驻进程有差异，根因尚未完全确认，不当作全局永久授权或自动重复申请。其他启动上下文只读诊断可记录 `open -n -W --stdout <全新输出文件> --stderr <全新错误文件> ~/Applications/Alfred.app --args --agenda ...`。CLI有60秒硬截止；权限回调有45秒截止，最多有限只读状态回查，无二次请求。拒绝/nil/超时不报告零条。提醒专用入口只查询/申请reminder，不调用calendar权限API；双实体旧入口保留但不得拿来代替专用入口。

只读核心范围文件 `read-request.json` 示例（替换为真实已经选定的列表ID，不执行占位文件）：

```json
{"allVisibleSources":false,"sourceIDs":[],"calendarIDs":["SELECTED-LIST-ID"],"eventStart":null,"eventEnd":null,"includeReminders":true,"timeZone":"Asia/Shanghai"}
```

`--agenda read read-request.json` 仅读取指定列表的已完成/未完成核心记录，不读备注。选中精确ID再读取备注/完成时间：

```json
{"targets":[{"entity":"reminder","sourceID":"ACTUAL-SOURCE","calendarID":"ACTUAL-LIST","appleID":"ACTUAL-ID","occurrenceStart":null}],"fields":["completionDate","notes"]}
```

`--agenda read-targets targets.json`。最多100个显式唯一目标，同名不会匹配身份；未选中的文本不视为空，选中但缺键表示原生nil。

## 预览与批准

批次保持schemaVersion=1：batchID、source{pageID/version/readAt/contentSHA256}、timeZone、operations。source证明必须来自实际重新读取的已批准来源；不能把本示例当真实Space记录，也不能伪造时间戳。原系统ID和稳定externalID共同维护；后者不是标题。

操作公共结构：id、externalID、action、target、baseline、changes、recurrenceScope=this、relationshipScope=none。baseline必须为上述真实读取的完整精确投影和modifiedAt，不按同名拼装。

- 追加备注：changes={"notes":"本人批准的新段落"}、notesMode=append；旧非空原文用双换行连接。
- 替换：notesMode=replace；清空原生nil：changes={}、clearFields=["notes"]、notesMode=replace。空串和nil不同。
- 完成：changes={"isCompleted":"true"}；恢复未完成：false。不修改due字段或闹钟，不输入completionDate。baseline须选择completionDate。
- 删除：action=delete、changes={}、allowIrrecoverableDelete=true，不能夹带notesMode/clearFields/其他修改。不保证原标识恢复。

完成/恢复/删除同时要求以下结构，由本人确实在原生界面核对后才生成；不能自动代本人核对。baselineSHA256用共享编码/哈希函数计算精确baseline，绑定身份、原字段及版本：

```json
{"reminderStandaloneReview":{"baselineSHA256":"REAL-BASELINE-SHA256","reviewedAt":"ACTUAL-REVIEW-TIME","reviewedBy":"human-user","statement":"Native UI verified standalone; no parent or children"}}
```

调用顺序：

```sh
~/Applications/Alfred.app/Contents/MacOS/SuiAssistant --agenda preview batch.json ledger-dir
# 人类检查完整差异、notes原文和删除/关系限制后，批准具体operationIDs。
~/Applications/Alfred.app/Contents/MacOS/SuiAssistant --agenda execute preview.json approval.json source-current.json ledger-dir
# 必须另起进程独立回读，不能用execute同进程即时回读代替。
~/Applications/Alfred.app/Contents/MacOS/SuiAssistant --agenda receipt BATCH-ID ledger-dir
~/Applications/Alfred.app/Contents/MacOS/SuiAssistant --agenda read-targets targets.json
```

approval结构为batchID、previewSHA256、operationIDs、approvedBy=human-user、approvedAt、statement="Approve exactly these operations and fields"。这是工作流证据，不是密码学身份验证，自动生成JSON不代表人类批准。执行前整体核对来源/基线，各项写前再次核对，局部未知后停止余项。跨设备仍无原子CAS保证。

## 逐项回执

receipt含batch、previewSHA256、approval、startedAt/finishedAt、sourceVerifiedAt、device、mappings，以及results[]：

```json
{"operationID":"OP-ID","status":"unknown","appleReference":null,"readback":null,"reason":"Write boundary entered; read back before retry","reminderWarnings":["Hierarchy UNKNOWN; human standalone review required"]}
```

状态pending/skipped/unknown/success有明确区别：skipped是批准集之外或前置条件变更未调用写入；unknown说明写边界已进入但保存/回读未确认，不武断当失败或成功。重复批次只核对，不重写；后来的手机修改不覆写，历史success与当前差异同时保留。permission/nil/read timeout错误不会变成空列表或删除成功。回执不会证明未投影的子任务/闹钟等字段已独立验收。
