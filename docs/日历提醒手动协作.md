# Alfred 手动日历协作

1.1.0/build28。常规菜单栏继续只读；以下CLI是按需手动入口，不创建后台同步。

## 操作流程

1. 用已安装应用 `Contents/MacOS/SuiAssistant --agenda status` 检查当前权限，命令不会申请权限。
2. 需要授权时，先明确批准该确切包的日历fullAccess请求，再使用 `--agenda request-calendar-access --user-approved-privacy-request`；该入口只处理日历。旧 `request-read-access` 会顺序处理日历＋提醒，必须单独批准两类范围。
3. 明确source/calendar/date范围后用 `--agenda read request.json` 获取核心字段；位置／备注用 `--agenda read-targets request.json`，需完整事件sourceID/calendarID/appleID/occurrenceStart及明确fields，最多100个唯一目标。不会全量复制备注。
4. 用 `--agenda preview batch.json ledger-dir` 查看精确差异；批次包含来源pageID/version/readAt/contentSHA256、stable externalID、目标基线和补丁。新增没有旧ID；已有目标须核对身份、modifiedAt与字段，不能按同名绑定。
5. 人工确认具体预览后才生成approval（batchID、previewSHA256、operationIDs、approvedBy=human-user、approvedAt、statement=Approve exactly these operations and fields）。用 `--agenda execute preview.json approval.json source-current.json ledger-dir` 执行；来源证明需真实新读取，不能修改时间戳伪装。
6. `--agenda receipt batch-id ledger-dir` 只核账本和回读，不重放。超时／unknown先核原账本；未知新建不自动认领候选或重建。

CLI不能直接登录Space取得来源证明；需要受支持的执行端真实读取并提供。批准校验是工作流约束，不是密码学身份验证，不能把自动生成文件当人类批准。个人基线与账本默认放Git忽略的.agenda-local（0700目录、0600账本）。勿将这些文件上传。

## 五字段与限制

标题、start/end/allDay/timeZone、location、来源／日历身份保留、notes。类别不迁移／新建。projectedFields标记明确读取的文本，选中缺键表示原生nil，空字符串另存，未选中不可当空。notesMode必须append或replace；append保留原文，用两个换行连接非空旧值。clearFields显式设nil，不与同字段changes混用；清除notes需replace。预览textDifferences显示完整before/after和null，批准哈希绑定模式、基线与文本。

全天end为排他：示例17–19日三天应结束在20日零点。只写批准补丁，保存后按返回身份读取相同投影；系统归一化导致不同值保留unknown。无跨设备原子CAS保证，重读与保存间仍可能竞争。邀请、重复／分离、忙闲、URL、闹钟、组织者、取消／删除与提醒完成均不支持；未批准字段不赋值。

权限已有fullAccess时不重复申请；一次回调最多45秒，CLI总60秒截止。callback允许但状态未确认最多另查10次、间隔0.2秒，仍未确认unknown并停止，不二次请求或续提醒。开发通过、系统权限与具体写入批准互不替代。

## 验证边界

95项／14套逻辑及模拟测试通过。冻结开发候选曾实际日历授权和限目标读取，早期标题／普通新增有批准后的实际回执；位置／备注已有实际保存回读成功；一个全天新增出现回读差异，保留unknown且不重放。公开安装包签名已改变，不能推定继承旧权限；其他Mac初装未验。日历持久修改应先独立预览和批准，未知结果不能盲目重试。
